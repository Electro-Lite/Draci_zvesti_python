# Draci zvesti merged

Python prototype for a two-player card game about preparing a board, revealing
mana, and fighting dragons. The repository contains:

- the game engine and card model,
- SQLite-backed card and deck storage,
- Tkinter tools for editing cards and decks,
- a Pygame local game UI,
- NEAT-based AI training for players, deck evaluation, and deck building,
- notebook-oriented analysis helpers for training results.

This is an active research/prototype codebase. Some old modules are kept for
reference, some command-line scripts are rough, and training can generate very
large local databases.

## Quick Start

Run commands from the repository root. Several modules use relative paths for
images, checkpoints, and `train.db`.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install neat-python pygame pillow pandas numpy plotly
```

Minimal runtime dependencies are:

```bash
python -m pip install neat-python pygame pillow
```

Analysis notebooks and chart helpers additionally need:

```bash
python -m pip install pandas numpy plotly
```

Tkinter is part of Python on many systems, but Linux distributions often package
it separately. If `import tkinter` fails, install the system package for your
Python version, for example `python3-tk`.

## Main Commands

### Card editor

```bash
python -m cards.card_builder_GUI
```

Use this to create, load, edit, and delete cards in `utils/cards.db`.

Important details:

- Image selection is restricted to `cards/card_images/`.
- Saved image paths are stored as relative paths such as
  `cards/card_images/Asketa.png`.
- Dragon cards are stored in the same `cards` table as player cards.
- `cards/dragons.py` expects these dragon card IDs to exist:
  `dragon_blue_1`, `dragon_red_1`, `dragon_green_1`, `dragon_black_1`.

### Deck editor

```bash
python -m cards.deck_builder_GUI
```

Use this to search saved cards, preview card details, assemble a deck, and save
or delete player-made decks in `utils/decks.db`.

Deck rules enforced by `Deck.validate()`:

- minimum 10 cards,
- maximum 12 cards,
- maximum 4 copies of normal cards,
- maximum 1 copy of cards whose `rarity` attribute is `"legendary"`.

Deck identities are generated by database utility code. For a deck named
`Starter Blue`, generated IDs look like `Starter Blue_1`, `Starter Blue_2`,
and so on.

### Pygame local game

```bash
python -m py_game.main
```

Controls:

- Arrow keys move through menu items, cards, and board positions.
- Enter confirms the highlighted menu item or selected game action.
- Backspace exits the active game view back to the menu.

The active menu flow supports local match setup and deck selection. The main
menu also shows placeholders for deck management and AI training, but those are
not wired into the Pygame menu.

### Clear training data

Dry run:

```bash
python -m neat_ai.clear_training_data
```

Delete all training data and old AI-generated decks referenced from
`utils/decks.db`:

```bash
python -m neat_ai.clear_training_data --yes
```

Delete one training run:

```bash
python -m neat_ai.clear_training_data --training-id 1 --yes
```

Keep old AI deck rows in `utils/decks.db` while clearing training tables:

```bash
python -m neat_ai.clear_training_data --keep-legacy-decks --yes
```

Without `--yes`, the command only reports the row counts that would be deleted.

## Game Concepts

### Cards

Cards are represented by `cards.card.Card`.

Main fields:

- `id`: database ID,
- `name`: display name,
- `power`: `STARTER`, `NORMAL`, or `LEGENDARY`,
- `color`: `RED`, `BLACK`, `BLUE`, or `GREEN`,
- `color_buf`: `[dmg_bonus, hp_bonus]` applied when current mana matches,
- `hp`: health,
- `dmg`: damage,
- `ability`: an `Ability` instance,
- `image`: relative image path,
- `type`: `PLAYER` or `DRAGON`.

### Mana

`cards.mana.get_mana_pool_shuffled()` creates a shuffled pool containing red,
black, and blue mana. At the start of each round, the board cycles the pool and
uses `mana_pool[0]` as the active mana color.

When a card's color matches active mana, its `color_buf` bonus is added during
board recalculation.

### Abilities

Abilities live in `cards/ability/abilities.py`. The base class records:

- human-readable name and description,
- NEAT ability ID,
- target owner,
- whether the ability is active,
- whether the ability is passive.

Implemented player-facing examples include:

- no ability,
- front-card attack buff,
- adjacent-card buff,
- move to first position,
- swap with previous card,
- attack the card directly in front.

Implemented dragon abilities include:

- remove the first board card,
- remove all cards with 1 or less HP,
- reverse the board order.

### Board

`core.board.Board` has six card positions. It also tracks:

- current dragon deck,
- active mana pool,
- current game state,
- current round,
- current player on turn,
- Pygame-facing state such as `winner` and `game_running`.

Board recalculation restores cards to their base stats, reapplies mana bonuses,
then reapplies passive abilities.

### Match Flow

The match loop is in `core.game_loop.run()`.

1. Create a board if one was not provided.
2. Build one `GameInfo` view per player.
3. Shuffle both decks.
4. Draw 5 cards per player.
5. Randomly choose who starts.
6. Each round:
   - reset pass flags,
   - clear old board cards after the first round,
   - draw up to 3 cards per player after the first round,
   - cycle mana,
   - alternate player turns.
7. On a turn, a player may pass or choose:
   - card,
   - empty board position,
   - whether to use an active ability,
   - ability target position.
8. The round ends when all six board positions are full or both players pass.
9. A dragon appears and fights board cards from position 0 to 5.
10. A player wins once their score reaches 2, or the game ends when both players
    run out of cards.

`Config.max_rounds` is currently 10. Exceeding it raises an error.

## Architecture

### Top-Level Layout

```text
cards/              Card model, card/deck GUI tools, card images, abilities
choice_strategies/  Human, random AI, Pygame, and NEAT decision strategies
core/               Board, player, game loop, game state
display_strategies/ CLI, Pygame, and no-op display adapters
neat_ai/            NEAT deck/player/evaluator trainers and analysis helpers
py_game/            Pygame menu and game UI
utils/              SQLite database utilities and one-off migration scripts
```

### Core Interfaces

`PlayerChoiceStrategy` defines the behavior a player must provide:

- `get_choice_pos()`
- `get_choice_card()`
- `get_choice_use_ability()`
- `get_choice_pass()`
- `get_choice_ability_target()`

Implemented strategies:

- `ChoiceStrategyAIRandom`: random legal-ish choices,
- `PlayerChoiceStrategyNeat`: choices from a NEAT feed-forward network,
- `PygameChoiceStrategy`: waits for choices from the Pygame UI,
- CLI strategy file: present, but naming/imports need cleanup before using it
  as a standalone script.

`DisplayStrategy` defines all output hooks used by the game loop. Production
training uses `DisplayStrategyNone` to avoid rendering overhead.

## Databases

Generated databases are local artifacts and are ignored by `.gitignore`.

### `utils/cards.db`

Stores all cards.

Logical schema:

```sql
cards(
  owner,
  id PRIMARY KEY,
  name,
  power,
  color,
  hp,
  dmg,
  color_dmg_buff,
  color_hp_buff,
  ability,
  image,
  type
)
```

Use `DBUtil.save_card()`, `DBUtil.load_card()`, `DBUtil.get_all_cards()`, and
`DBUtil.delete_card()` rather than writing direct SQL in new code.

### `utils/decks.db`

Stores player-made decks.

Logical schema:

```sql
decks(
  id PRIMARY KEY,
  name,
  description,
  power,
  fitness,
  is_AI DEFAULT 0,
  signature
)

deck_lines(
  deck_id,
  card_id,
  signature
)
```

`signature` is a hash of sorted card IDs. Deck lines are shared by signature,
so identical compositions can reuse the same composition rows. `DBUtil`
filters AI-marked decks out of normal deck listings by default.

### `train.db`

Stores AI training runs and training-generated decks.

Important tables:

- `training`: one row per outer training session,
- `genome`: one row per saved deck-builder genome,
- `match_dbt`: outer deck-vs-deck match rows,
- `pc_match`: inner player-controller match samples,
- `ai_training_decks`: decks generated by training,
- `ai_training_deck_lines`: card lines for those generated decks.

New AI training decks are intentionally stored in `train.db`, not in
`utils/decks.db`, so player-made decks can be kept clean.

## AI Training

The AI code uses `neat-python`.

Training outputs may include:

- `train.db`,
- `training_progress.txt`,
- `neat_ai/training_progress.txt`,
- checkpoint files under `neat_ai/checkpoints/`,
- winner pickles under `neat_ai/trained_ai/`.

These files can become large. The current local `train.db` is hundreds of MB.

### Player Controller Training

Entrypoint:

```bash
python -m neat_ai.player_trainer
```

Current behavior:

- trains NEAT player controllers on a hardcoded `Starter Blue_1` deck,
- uses `neat_ai/configs/neat_config_player.txt`,
- current config has `pop_size = 10`, `num_inputs = 152`,
  `num_outputs = 5`,
- saves a winner pickle under `neat_ai/trained_ai/`.

The script defines an argparse `deck_id`, but the parse call is currently
commented out and the hardcoded deck is used. To train another deck without
editing the script, call `train_deck(DBUtil().load_deck("Deck ID"))` from a
small Python snippet.

### Deck Evaluator Training

Entrypoint:

```bash
python -m neat_ai.deck_evaluator "Deck One ID" "Deck Two ID"
```

Current behavior:

- trains player-controller populations for both decks,
- uses `neat_ai/configs/neat_config_evaluator.txt`,
- current config has `pop_size = 15`, `num_inputs = 152`,
  `num_outputs = 5`,
- the evaluator is used by the deck-builder trainer to score generated decks,
- when called from the deck-builder trainer, it logs `pc_match` rows linked to
  the current outer match GUID.

### Deck Builder Training

Entrypoint:

```bash
python -m neat_ai.deck_builder_trainer
```

Current behavior:

- uses `neat_ai/configs/neat_config_builder.txt`,
- current config has `pop_size = 5`, `num_inputs = 91`,
  `num_outputs = 2`,
- builds one candidate deck per genome,
- saves generated decks to `train.db` with `save_training_deck()`,
- logs genomes and outer matches,
- evaluates every pair of generated decks in a generation,
- saves the final winner to `neat_ai/trained_ai/best_builder_<generation>.pickle`.

This is expensive because the outer deck-builder loop runs nested evaluator
training for deck pairs. Start with very small config values when debugging.

### Training Cleanup

Use the cleanup command before starting a fresh experiment:

```bash
python -m neat_ai.clear_training_data
python -m neat_ai.clear_training_data --yes
```

The first command is a dry run. The second performs deletion.

For safer workflow:

1. Run a dry run.
2. Check the counts.
3. Back up `train.db` or `utils/decks.db` if needed.
4. Re-run with `--yes`.

## Analysis

Analysis helpers live under `neat_ai/analysis/`.

Recommended setup:

```bash
source .venv/bin/activate
python -m pip install pandas numpy plotly
```

Useful modules:

- `data_loader.py`: opens `train.db` and attaches `utils/decks.db`,
- `card_metrics.py`: card tier list and power ratings,
- `synergies.py`: pair co-occurrence in successful decks,
- `matchups.py`: deck matchup summaries and matrices,
- `balancer.py`: likely nerf/buff candidates,
- `learning_curves.py`: player-controller learning curves per deck,
- `academic_metrics.py`: entropy, diversity, matchup balance, viability,
- `insight_charts.py`: Plotly chart builders.

Example:

```python
from neat_ai.analysis.card_metrics import get_card_power_rating
from neat_ai.analysis.matchups import get_matchup_summary

print(get_card_power_rating(min_times_played=3).head())
print(get_matchup_summary().head())
```

Optional SQLite indexes for repeated notebook work:

```python
from neat_ai.analysis.data_loader import ensure_analysis_indexes
ensure_analysis_indexes()
```

See `neat_ai/analysis/GRAPH_EXPLANATIONS.md` for the intended meaning of the
main charts.

## Common Maintenance Tasks

### Fix card image paths

If card images were saved with absolute or Windows-style paths, normalize them:

```bash
python -c "from utils.fix_paths import fix_image_paths; fix_image_paths('utils/cards.db')"
```

### Migrate old deck signatures

For an old `utils/decks.db` missing `signature` columns:

```bash
python -m utils.one_time_deck_db_fix
```

Current `DBUtil` also adds missing `signature` and `is_AI` columns on startup.

### Check database contents

```bash
sqlite3 utils/cards.db ".tables"
sqlite3 utils/decks.db ".tables"
sqlite3 train.db ".tables"
```

### Compile-check source files

```bash
python -m py_compile \
  cards/*.py \
  cards/ability/*.py \
  choice_strategies/*.py \
  core/*.py \
  display_strategies/*.py \
  neat_ai/*.py \
  neat_ai/analysis/*.py \
  py_game/*.py \
  py_game/menu/*.py \
  utils/*.py
```

## Known Rough Edges

- There is no `requirements.txt` or `pyproject.toml` yet.
- `core/test_run.py` is not a reliable standalone CLI runner right now. It
  imports a CLI strategy name that does not match the class defined in
  `choice_strategies/choice_strategy_human_CLI.py`.
- `py_game/old/` contains older Pygame experiments and should not be treated as
  the primary UI.
- `neat_ai/player_trainer.py` has an argparse placeholder but currently trains
  the hardcoded `Starter Blue_1` deck.
- Some GUI code still reads deck rows directly with SQL. Prefer `DBUtil` for new
  code so AI deck filtering and migrations are centralized.
- `AITrainingLogger` opens `train.db` relative to the current working directory,
  so run training commands from the repository root.
- The training database can grow quickly. Use `neat_ai.clear_training_data` for
  fresh experiments.

## Git Hygiene

The `.gitignore` excludes:

- Python bytecode and cache folders,
- virtual environments,
- local SQLite databases,
- generated checkpoints,
- generated trained AI pickle files.

Do not commit generated `.db`, checkpoint, pickle, `.pyc`, or virtual
environment files unless there is an explicit reason.
