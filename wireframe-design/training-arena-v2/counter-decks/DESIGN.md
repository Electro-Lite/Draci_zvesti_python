# Counter-deck training

Question: **Which generated deck counters the selected deck, and how does its card composition differ?** The user's selected deck is the subject; the evolved counter is the adversary. A top-counter win rate must always be labeled “counter win rate versus [selected deck]”, never an unlabeled “win rate”. The full final candidate set should be selectable, with its own wins, draws, losses, games and composition.

Two directions:

1. [Compositions first](01-compositions-first.png) keeps both full card lists, the selected candidate's head-to-head outcome and a candidate list in one screen. It is easiest for a beginner to answer “what beat me?” without opening another page.
2. [Investigation board](02-investigation-board.png) lets a user choose among candidates, compares per-card copy counts, then presents that candidate's result. It is an unselected study. [Inspect both decks](03-deck-inspector.png) is also unselected; the chosen Compositions first board shows both complete decks directly and has **no inspect-deck button**.

The compositions first board uses the real Starter Blue deck from `utils/decks.db`: Lucisnik, Paladin, Panos, Pesak and Strazny, two copies each. The counter composition is a real final candidate, Counter G1 #8: Draci Fanatik ×4, Pesak ×2, and Asketa, Dummy, Innosuv Fanatik, Lucisnik, Novic and Paladin ×1 each. Its four shared card copies are Pesak ×2, Lucisnik ×1 and Paladin ×1. **The 1,000-game result is illustrative, not this historical candidate's measured result**: 800 counter wins, 100 draws and 100 selected-deck wins. The historical local run had only 16/2/2 in 20 games. Names, counts and mana-color markers are visible; card artwork can be added as a secondary visual if available.

The chosen **Compositions first** screen has a run-depth line directly below that candidate's result. Its illustrative plan uses one counter-deck generation and ten controller-learning generations. With 20 legal candidates each tested in **1,000 seat-balanced games**, validation takes **20,000 games**. Two persistent controller populations are configured for 15 genomes each; all 15×15 pairings per learning generation imply **about 2,250 controller-learning games**, or **about 22,250 scheduled simulations** including validation. Label validation from recorded candidate counts separately from estimated learning workload; fewer than 20 legal candidate decks are possible, so do not report 20,000 as completed unless the summary proves it. If exact learning-game counts become available, use them and remove the approximation. Do not call a candidate's 1,000 validation games “matches per genome”—a counter deck candidate and a controller genome are different entities.

`neat_ai/counter_deck_trainer.py` stores `subject_cards` and final `counter_matchups` in the summary, including `cards`, `card_names`, `games`, `counter_wins`, `draws`, `subject_wins`, `counter_win_rate`, `counter_fitness` and `shared_cards`. The current Arena only exposes the top candidate name/rate and total candidate count through `TrainingInsights`, so a future implementation would need to read final candidates into a presentation model. Before any candidate exists, show training phase and “No counter decks evaluated yet”. After a partial generation, mark candidate results “partial”. If card metadata cannot be resolved, show IDs and counts rather than dropping the row.

The result strip is a **100%-stacked green / gray / red bar**: selected counter wins / draws / selected deck wins, using all games as the denominator. **Each segment shows its own share directly inside it**—80% / 10% / 10% in the example—in addition to the W/D/L counts above. Green is not an unlabeled generic “win”; it belongs to the selected counter. If a real segment is too narrow for a readable label, place that percentage immediately beside the bar with a matching color/leader rather than squeezing or hiding it. Keep the pooled selected-deck win rate across the evolving population separate from the selected candidate's own head-to-head score. The design treats **1,000 evaluation games per candidate as the minimum target for a stable comparison**, not a guarantee of truth or universal counter strength. Historical and exploratory runs below 1,000 remain visible with their actual sample count and a prominent “exploratory sample; below 1,000-game comparison target” warning. Selection among 20 candidates still introduces winner's-curse/multiple-comparison risk; communicate that in methodology. Offer sample count and seat-balance context wherever a rate appears.
