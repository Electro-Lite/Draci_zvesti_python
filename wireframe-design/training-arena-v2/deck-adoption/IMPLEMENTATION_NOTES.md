# Adoption implementation contract

1. Launch only from a **completed** Counter or Deck Evolution result; never from in-progress/terminal-no-result screens. Bind the action to the currently selected candidate/generated deck, not the top record if another is selected.
2. Counter source: selected candidate's `cards` snapshot in the completed `summary.json` `counter_matchups`; verify card IDs/counts and show names using current card metadata. Deck Evolution source: selected stored `ai_training_decks` row and its `ai_training_deck_lines` in `train.db`; cover any stored generated deck for that completed run, not only the final winner. Do not mutate those sources.
3. Naming dialog: show source, exact composition/count, a nonempty editable name with the deck editor's existing length/validation rules, and clear “Save as my deck”/Cancel. Make dialog keyboard-accessible. Name conflicts or same-signature/same-name existing user decks require a clear choice to open existing or choose another name. Do not silently overwrite.
4. **Create a new `Deck()` with no source ID.** Resolve/copy full card objects by ID, preserve exact multiplicity and any meaningful ordering, validate using normal user-deck rules, then call the existing save path with `is_ai=False`. `DBUtil.save_deck` may UPSERT when `deck.id` is set; passing a generated ID risks source overwrite. The success path must verify persisted new/user-deck identity. Do not relabel an AI record in place, modify training DB, or delete the original.
5. Refresh relevant My decks lists and deck pickers after a successful save. Only then display success with Open in editor and Back to results. On DB failure/missing card/illegal composition, keep results/source intact, show a specific error, and avoid a half-saved or falsely successful state. If the current card catalog makes an old artifact invalid, report it; never silently repair it.

Focused tests: selected-but-not-top source, exact counts, distinct ID, `is_AI=0`, original artifact unchanged, name validation, same-name duplicate, missing/retired card IDs, invalid 10–12-card/copy rules, persistence failure, picker refresh, and prevention of adoption for active/failed runs. Inspect the current schema/API before implementation; source field names here describe the observed repository, not a mandate to bypass its service layer.
