Preserve training/setup/Runs, safe stop confirmation, logs, and existing completed mission views.

Before completion, every mission routes to one shared progress screen with the old dashboard's visual spirit: prominent overall progress or indeterminate ring, phase lane, real nested counters, elapsed time, defensible ETA/“Estimating…”, and recent events. Tailor metric labels to counter finding, matchup evaluation, and deck evolution; never relabel pairings as games or invent inner-loop progress. Do **not** show mission-specific result tables, candidate compositions, matchup win rates, evolution analysis pages, or Adopt deck while the job is pending/running/stopping.

Route on authoritative completion, not on a 100% counter. Once completed and the result artifact is valid, retain a one-time in-session completion handoff with a clear **“Open [mission] results”** button; do not auto-transition. If artifact readiness lags, show “Preparing results…” with disabled action and retry/error state. If a completed run is opened later from Runs, go directly to its own mission-result layout. Stopped/failed/cancelled/interrupted/historical incomplete runs get terminal status/logs, not finished-result layouts. A live job may remain visible while stopping; Stop requires existing confirmation and applies only where supported.

Use currently available telemetry honestly and add instrumentation only if needed within scope. ETA may use measured completed units or current trainer telemetry; otherwise show “Estimating…”, not a fake number. Keep I/O and aggregation outside draw calls, support 1600×900, 1280×720, 640×480 by scrolling, and test state transitions, artifact lag, stale/missing telemetry, ETA fallback, navigation and stop behavior. Deck Evolution’s finished “Run pulse” page is retrospective and remains part of its five-page result design, not this active-run view. Report changes, tests and limits.
